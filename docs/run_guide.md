# Быстрый запуск КОРПУС

Как развернуть и запустить систему на новой машине. Рассчитано на то, что вы получили
**архив с решением** (или клонировали репозиторий), и хотите запустить его «одним файлом».

---

## Что нужно на компьютере

- **Если в поставке есть папка `runtime\`** (вшитый Python для Windows) — **не нужно
  ничего устанавливать**: ни Python, ни Node. Просто запустите `START.bat`. Этого
  достаточно на «голой» Windows с одним браузером. (Только x64-Windows.)
- **Если папки `runtime\` нет** — нужен установленный **Python 3.10+** (рекомендуется 3.12;
  проверить: `python --version` или `py -V`; скачать <https://www.python.org/downloads/>,
  при установке отметить **«Add Python to PATH»**) и **интернет** на первый запуск, чтобы
  один раз скачать зависимости.
- **Node.js НЕ требуется** ни в одном случае: веб-интерфейс уже собран и входит в поставку
  (`web/frontend/dist`); сервер отдаёт его сам.

API-ключи нейросетей **не обязательны**: базовый анализ (метрики, критические вопросы,
анализ попыток) работает офлайн, без обращения к ИИ. Ключи нужны только для
ИИ-комментариев и чата — см. раздел «Ключи API» ниже.

---

## Запуск одним файлом (рекомендуется)

1. Распакуйте архив с решением в любую папку.
2. Запустите файл запуска:
   - **Windows:** двойной клик по **`START.bat`** (в корне проекта);
   - **macOS / Linux:** в терминале из папки проекта — `chmod +x start.sh` (один раз),
     затем `./start.sh`.
3. Дождитесь сообщения о запуске. С вшитым `runtime\` запуск **мгновенный**. Если
   `runtime\` нет, **первый** запуск создаёт окружение и ставит зависимости — 1–3 минуты
   и требуется интернет; последующие — быстрые.
4. Браузер откроется автоматически на адресе вида `http://127.0.0.1:8010/`. Если не
   открылся — откройте этот адрес вручную (точный порт скрипт печатает в окне).

Что делает `START.bat` / `start.sh` (через `scripts/launch.py`):

```
выбрать Python (вшитый runtime\ → .venv → системный)  →  при необходимости создать
.venv и поставить зависимости  →  проверить собранный UI  →  поднять сервер
web.serve:app на свободном порту  →  открыть браузер
```

**Остановить:** закройте окно консоли или нажмите в нём `Ctrl+C`.

## Проверка, что всё работает

1. На вкладке **«Новый анализ»** перетащите в карточку «Ответы пользователей» любой
   пример из поставки, например `data/samples/021/Массив ответов*.xlsx`, а в «Эталонные
   ответы» — соответствующий `data/etalon/021/Эталон*.xlsx`.
2. Нажмите **«Запустить анализ»**. Откроется вкладка «Результаты» с метриками,
   критическими вопросами и анализом попыток.

## Ключи API (опционально — для ИИ-функций)

Ключи хранятся в файле `.env` в корне проекта (в репозиторий не попадают). Скопируйте
шаблон и впишите свои значения:

```
copy .env.example .env      :: Windows
cp   .env.example .env       # macOS / Linux
```

Переменные:

| Переменная | Для чего |
|---|---|
| `OPENROUTER_API_KEY` | Зарубежная группа моделей (OpenRouter). |
| `GIGACHAT_CREDENTIALS` | Российская группа (GigaChat) — авторизационные данные. |
| `GIGACHAT_SCOPE` | Область доступа GigaChat (напр. `GIGACHAT_API_PERS`). |

Без `.env` приложение запустится и будет считать анализ по коду; при попытке включить
ИИ-комментарии без ключа появится понятное сообщение об ошибке.

## Запуск из командной строки (CLI)

Для пакетной обработки и для форматов **JSON / CSV / папки с файлами** удобен CLI —
он работает напрямую с движком, минуя веб-интерфейс:

```bash
# .xlsx (примеры из поставки)
python main.py --input data/samples/021 --reference data/etalon/021 --mode all

# JSON / CSV (примеры в data/samples_jsoncsv) — формат определяется по расширению
python main.py --input data/samples_jsoncsv/json --mode all
python main.py --input data/samples_jsoncsv/csv  --mode all

# с обращениями к ИИ (нужен ключ в .env): ограничьте число вызовов
python main.py --input data/samples/001 --reference data/etalon/001 --max-llm-calls 20
```

`--input` принимает **файл или папку** (папка сканируется рекурсивно). Поддерживаемые
форматы входа и их структура описаны в `docs/input_formats.md`. По умолчанию LLM не
вызывается (`--max-llm-calls 0`) — это бесплатный анализ «по коду». Отчёты сохраняются
в `./output`.

## Ручной запуск без лаунчера (для разработчиков)

**Продакшен-режим (Python-only, как делает лаунчер):**

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt    # Windows
python -m uvicorn web.serve:app --host 127.0.0.1 --port 8010
```

**Режим разработки (горячая пересборка фронтенда, нужен Node 18+):**

```bash
# терминал 1 — backend
python -m uvicorn web.app:app --port 8010
# терминал 2 — frontend (Vite проксирует API на backend)
cd web/frontend && npm ci && npm run dev
```

В dev-режиме интерфейс открывается на порту Vite (по умолчанию 5173), а API-запросы
проксируются на backend. Если backend поднят не на 8000, укажите цель прокси:
`VITE_API_TARGET=http://127.0.0.1:8010`.

## Сборка вшитого runtime (для подготовки поставки, Windows)

Чтобы архив запускался на «голой» Windows без установки Python, в проект вшивается
портативный Python с зависимостями. Соберите его **один раз** на машине с Python и
интернетом:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\bundle_runtime.ps1
```

Скрипт скачивает Windows embeddable Python 3.12, кладёт его в `runtime\python`, ставит
туда зависимости и проверяет импорт проекта (~80 МБ). После этого `START.bat` сам
предпочитает `runtime\python` и не требует системного Python. Папка `runtime\` не
коммитится в git — включайте её прямо в архив поставки.

## Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| «Python не найден» при запуске `START.bat` | Установите Python 3.10+ и отметьте «Add Python to PATH», перезапустите. |
| Долгий первый запуск | Это установка зависимостей — дождитесь; нужен интернет. |
| «Не найден собранный интерфейс … dist» | Поставьте Node.js 18+ и выполните `cd web/frontend && npm ci && npm run build`. |
| Порт занят | Лаунчер сам выберет следующий свободный порт; смотрите адрес в окне консоли. |
| Не ставятся зависимости | Проверьте интернет; вручную: `.venv\Scripts\python -m pip install -r requirements.txt`. |

См. также: `docs/user_guide.md` (как пользоваться интерфейсом), `docs/admin_guide.md`
(администрирование, модели, ключи), `docs/developer_guide.md` (архитектура и код).
