# Форматы входных данных КОРПУС C2

Система принимает результаты тестов в трёх форматах: **Excel (`.xlsx`)**,
**JSON (`.json`)** и **CSV (`.csv`)**. Любой формат можно передать как один файл
или как **папку** — папка сканируется рекурсивно, и каждый файл разбирается
парсером по своему расширению.

Для каждого курса нужны два вида файлов:

| Вид | Что содержит | Классификация по имени файла |
|-----|--------------|------------------------------|
| **Массив ответов** | попытки студентов и их ответы | имя содержит слово `массив` (или не содержит `эталон`) |
| **Эталон ответов** | правильные ответы (ключ) | имя содержит слово `эталон` |

Все три формата дают на выходе одни и те же объекты модели
(`StudentAttempt` / `QuestionAnswer` / `ReferenceAnswer` из `core/models.py`),
поэтому остальная часть движка не меняется.

> Готовые образцы всех форматов лежат в `data/samples_jsoncsv/`.

---

## 1. Excel (`.xlsx`) — исходный формат

«Широкий» табличный формат, по одному листу на тест.

* **Массив ответов** — строки 0–1 это заголовки, далее по одной строке на
  попытку. Колонки: `Пользователь | Дата | Статус | Баллы`, затем блок из
  четырёх колонок на каждый вопрос: `Тип | Результат | Полученный ответ |
  Правильный ответ`. Заголовок вопроса в строке 0 объединён по этим четырём
  колонкам.
* **Эталон ответов** — строка 0 это тексты вопросов (по колонке на вопрос),
  строка 1 — метки `Правильный ответ`, далее канонические ответы.

Парсеры: `pipeline/parsers/answer_array_parser.py`,
`pipeline/parsers/reference_parser.py`. Этот формат остаётся без изменений;
ниже описаны новые JSON и CSV.

---

## 2. JSON (`.json`)

JSON-схема намеренно повторяет модель данных: объект попытки строится прямо из
файла через Pydantic `model_validate`.

### 2.1. Массив ответов — `answers.json`

Файл — это **список** объектов-попыток. Поля попытки повторяют `StudentAttempt`,
вложенный список `answers` — `QuestionAnswer`.

Поля попытки:

| Поле | Тип | Обяз. | Описание |
|------|-----|:----:|----------|
| `student_id` | строка | да | идентификатор студента |
| `test_name` | строка | да | название теста |
| `attempt_id` | строка | нет | если нет — генерируется автоматически |
| `attempt_date` | строка (дата) | нет | `ГГГГ-ММ-ДД ЧЧ:ММ:СС`, ISO или `ДД.ММ.ГГГГ` |
| `score_points` | целое | нет | набранные баллы (по умолчанию 0) |
| `score_max` | целое | нет | максимум баллов (по умолчанию 0) |
| `score_pct` | число | нет | процент; если нет — считается из баллов |
| `status` | строка | нет | напр. `Пройден` |
| `is_abandoned` | bool | нет | если нет — выводится автоматически |
| `answers` | список | нет | ответы (см. ниже) |

Поля ответа (`answers[]`):

| Поле | Тип | Обяз. | Описание |
|------|-----|:----:|----------|
| `question_text` | строка | да | текст вопроса (синоним: `question`) |
| `question_type` | строка | нет | `единственный выбор`, `множественный выбор`, `текстовый ввод`, `числовой ввод`, `соответствие`, `ранжирование`; иначе `неизвестно` |
| `given_answer` | строка | нет | ответ студента (синоним: `given`) |
| `correct_answer` | строка | нет | правильный ответ (синоним: `correct`) |
| `result` | строка | нет | вердикт LMS. Дружественные значения: `верно`/`неверно` (а также `correct`/`wrong`, `+`/`-`) либо сырой код LMS. Синоним поля: `result_code` |
| `is_answered` | bool | нет | если нет — `true`, когда есть `given_answer` |

Пример:

```json
[
  {
    "attempt_id": "a-ivanov-1",
    "student_id": "ivanov",
    "test_name": "Геометрия. Базовый тест",
    "attempt_date": "2025-10-23 10:20:00",
    "score_points": 2,
    "score_max": 3,
    "status": "Пройден",
    "answers": [
      {"question_text": "Сколько сторон у треугольника?", "question_type": "числовой ввод", "given_answer": "3", "correct_answer": "3", "result": "верно"},
      {"question_text": "Столица России?", "question_type": "текстовый ввод", "given_answer": "Москва", "correct_answer": "Москва", "result": "верно"},
      {"question_text": "Выберите чётные числа", "question_type": "множественный выбор", "given_answer": "2,4", "correct_answer": "2,4,6", "result": "неверно"}
    ]
  }
]
```

### 2.2. Эталон ответов — `reference.json`

Файл — это **список** записей-эталонов. Каждая запись описывает один правильный
ответ. Вопросы группируются в `{test_name: {нормализованный_вопрос: ...}}` той
же нормализацией, что и в xlsx-эталоне.

| Поле | Тип | Обяз. | Описание |
|------|-----|:----:|----------|
| `test_name` | строка | да | название теста |
| `question` | строка | да | текст вопроса (синоним: `question_text`) |
| `correct_answer` | строка | нет | канонический ответ (синоним: `raw_answer`) |
| `acceptable` | список строк | нет | допустимые варианты; если нет — выводятся из `correct_answer` |

Пример:

```json
[
  {"test_name": "Геометрия. Базовый тест", "question": "Сколько сторон у треугольника?", "correct_answer": "3"},
  {"test_name": "Геометрия. Базовый тест", "question": "Столица России?", "correct_answer": "Москва", "acceptable": ["Москва", "г. Москва"]},
  {"test_name": "Геометрия. Базовый тест", "question": "Выберите чётные числа", "correct_answer": "2,4,6"}
]
```

## 3. CSV (`.csv`)

Плоский «длинный» формат. Заголовки колонок распознаются без учёта регистра;
кодировка UTF-8 (BOM допускается).

### 3.1. Массив ответов — `answers.csv`

**Одна строка = один отвеченный вопрос.** Строки с одинаковыми
`student_id` + `attempt_id` (или `student_id` + `test_name`, если `attempt_id`
не задан) собираются в одну попытку; поля уровня попытки берутся из первой
строки группы.

| Колонка | Обяз. | Описание |
|---------|:----:|----------|
| `attempt_id` | нет | id попытки (если нет — генерируется) |
| `student_id` | да | идентификатор студента |
| `test_name` | да | название теста |
| `attempt_date` | нет | дата попытки |
| `score_points` | нет | набранные баллы |
| `score_max` | нет | максимум баллов |
| `status` | нет | напр. `Пройден` |
| `question` | да* | текст вопроса (*в строках с ответом) |
| `question_type` | нет | тип вопроса (см. JSON выше) |
| `given_answer` | нет | ответ студента |
| `correct_answer` | нет | правильный ответ |
| `result` | нет | вердикт: `верно`/`неверно` и т.п. (синоним: `result_code`) |

`score_pct` считается из `score_points`/`score_max`. Значения с запятыми
(например `2,4,6`) заключаются в кавычки по правилам CSV.

Пример:

```csv
attempt_id,student_id,test_name,attempt_date,score_points,score_max,status,question,question_type,given_answer,correct_answer,result
a-ivanov-1,ivanov,Геометрия. Базовый тест,2025-10-23 10:20:00,2,3,Пройден,Сколько сторон у треугольника?,числовой ввод,3,3,верно
a-ivanov-1,ivanov,Геометрия. Базовый тест,2025-10-23 10:20:00,2,3,Пройден,Выберите чётные числа,множественный выбор,"2,4","2,4,6",неверно
```

### 3.2. Эталон ответов — `reference.csv`

**Одна строка = один правильный ответ.**

| Колонка | Обяз. | Описание |
|---------|:----:|----------|
| `test_name` | да | название теста |
| `question` | да | текст вопроса |
| `correct_answer` | нет | канонический ответ (синоним: `raw_answer`) |
| `acceptable` | нет | допустимые варианты через `;`; если пусто — выводятся из `correct_answer` |
| `type` | нет | тип вопроса (информационно, не сохраняется) |

Пример:

```csv
test_name,question,correct_answer,acceptable,type
Геометрия. Базовый тест,Сколько сторон у треугольника?,3,,числовой ввод
Геометрия. Базовый тест,Столица России?,Москва,Москва;г. Москва,текстовый ввод
Геометрия. Базовый тест,Выберите чётные числа,"2,4,6",,множественный выбор
```

## Загрузка папок и ошибки

* На вход можно подать **папку** — будут найдены все `.xlsx`, `.json`, `.csv`
  (рекурсивно), классифицированы по имени (`массив`/`эталон`) и разобраны
  парсером по расширению.
* Битый JSON, отсутствие обязательного поля или пустой CSV приводят к понятной
  ошибке на русском языке; загрузчик собирает её как предупреждение и не
  прерывает разбор остальных файлов.

## Что программа прощает и чего не умеет

Прощает (без правки кода, при необходимости - на экране «Что я распознал»):

* служебные листы («Сводка», «Информация») и строки-шапки над таблицей;
* переименованные заголовки («Логин слушателя», «Дата и время попытки», «Результат попытки»,
  «Набрано баллов»), лишние колонки («№», «Время, мин»), пустые строки внутри таблицы;
* статусы «Пройден / Зачтено / Зачёт / Сдан» и их отрицания;
* баллы вида `12 / 15 (80%)` и `12,5 из 20 (62,5 %)`; даты как датой Excel, так и текстом;
* результат ответа кодами LMS или словами «Верно / Неверно», а также «Частично»
  (засчитывается как 0,5 балла);
* отличия заголовков вопросов между Массивом и Эталоном: пробелы, неразрывный пробел,
  знаки на конце, «е/ё», регистр имени листа;
* Эталон «вопросы по строкам» (колонки `№ | Вопрос | Правильный ответ`, лист на тест);
* файл-«широкая таблица» в формате CSV (шапка «Тест: …» над таблицей);
* испорченное кодировкой имя файла («РњР°СЃСЃРёРІ…»).

Не умеет (сознательно): **повреждённый или обрезанный `.xlsx`** открыть нельзя. Такой файл
пропускается с понятным сообщением («Файл … повреждён, обрезан … выгрузите заново»),
остальные файлы обрабатываются, анализ не останавливается.
