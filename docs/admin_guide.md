# Руководство администратора

Документ описывает установку, конфигурацию и запуск системы **КОРПУС C2** —
группы ИИ-агентов для анализа результатов тестовых заданий e-learning-курсов
Корпоративного университета Санкт-Петербурга.

Система состоит из двух частей:

- **Бэкенд** — Python: конвейер агентов (`agents/*`, `pipeline/*`), CLI-точка
  входа `main.py` и веб-сервер FastAPI `web/app.py`.
- **Фронтенд** — React + Vite + TypeScript в `web/frontend/` (одностраничное
  приложение, SPA), обращающееся к бэкенду через прокси.

> Принцип проекта: **«сначала код, ИИ — в последнюю очередь»** (`code-first,
> LLM-last`). Базовый прогон детерминирован и не обращается к нейросети
> (`--max-llm-calls 0`), поэтому стоит **0 токенов**. Обращения к LLM включаются
> явно. Ничего о моделях, ключах, путях и порогах не «зашито» в Python — всё
> читается из `config.yaml` и `.env`.

## 3. Конфигурация: `config.yaml`

Файл `config.yaml` в корне проекта хранит **только несекретные настройки**.
Секреты (ключи API) туда не пишутся — они задаются в `.env` и упоминаются в
`config.yaml` лишь по имени переменной окружения (`api_key_env`).

### 3.1. Активная группа моделей

```yaml
model_group: foreign        # "foreign" (OpenRouter) | "russian" (GigaChat)
```

Это группа по умолчанию. Её можно переопределить флагом CLI `--model-group`
или на экране «Настройки» в веб-интерфейсе (отдельно по компонентам).

### 3.2. Группы моделей `models`

Описаны две группы — **иностранная** (`foreign`) и **российская** (`russian`):

```yaml
models:
  foreign:
    provider: openrouter
    base_url: https://openrouter.ai/api/v1
    api_key_env: OPENROUTER_API_KEY
    model: deepseek/deepseek-v4-flash
    reasoning: false
    max_tokens: 1024
    temperature: 0.0
  russian:
    provider: gigachat
    api_key_env: GIGACHAT_CREDENTIALS
    scope_env: GIGACHAT_SCOPE
    model: GigaChat                 # тариф Lite — наибольший бесплатный лимит (900K токенов)
    verify_ssl: false
    max_tokens: 1024
    temperature: 0.0
```

Поля группы:

| Поле | Назначение |
|------|------------|
| `provider` | `openrouter` или `gigachat` |
| `base_url` | базовый URL API (для OpenRouter) |
| `api_key_env` | **имя** переменной окружения с ключом (значение в `.env`) |
| `scope_env` | имя переменной со scope (только GigaChat) |
| `model` | slug модели; для OpenRouter меняется свободно (см. openrouter.ai/models) |
| `reasoning` | у моделей-«рассуждателей» отключено для экономии токенов |
| `verify_ssl` | у GigaChat по умолчанию `false` (см. примечание ниже) |
| `max_tokens`, `temperature` | параметры генерации (по умолчанию `0.0` — детерминизм) |

> **Примечание о GigaChat и TLS.** GigaChat обслуживает TLS через корневой
> сертификат Минцифры. Прагматичная настройка по умолчанию — `verify_ssl:
> false`. Чтобы усилить безопасность, установите корневой сертификат Минцифры
> в систему и выставьте `verify_ssl: true`.

> **О выборе группы по умолчанию.** `foreign` (OpenRouter) отправляет ответы на
> зарубежный шлюз. Перед работой с реальными корпоративными данными, которые
> должны оставаться в РФ, переключите `model_group` на `russian` (GigaChat).

### 3.3. Пороги анализа `thresholds`

```yaml
thresholds:
  critical_correct_rate: 0.5   # вопрос помечается «критическим» ниже этой доли правильных
  fast_factor: 0.3             # время < медиана * fast_factor → подозрение на списывание/подсмотр
  slow_factor: 3.0             # время > медиана * slow_factor → подозрение на затруднение
  fuzzy_accept: 0              # 0 = нечёткое авто-принятие ВЫКЛ (близкие промахи → к LLM)
  min_samples: 10              # минимум ответов, прежде чем вопрос можно пометить «критическим»
```

- `critical_correct_rate` — порог «критичности» вопроса по доле верных ответов.
- `min_samples` — защита от малой выборки: вопрос не помечается критическим,
  пока ответов меньше указанного числа.
- `fuzzy_accept` — порог нечёткого совпадения с эталоном (rapidfuzz). `0`
  отключает авто-приём близких совпадений; для контента без орфографических
  ловушек можно поднять до ~95. Точное/числовое/множественное сравнение
  работают всегда.
- `fast_factor` / `slow_factor` — границы временных аномалий относительно
  медианы (агент времени).

### 3.4. Пути и бюджеты токенов

```yaml
paths:
  input: ./data/samples       # массив ответов пользователей
  reference: ./data/etalon     # эталонные ответы
  output: ./output             # отчёты

token_budget:
  foreign: 50000     # ориентир на курс (OpenRouter)
  russian: 30000     # ориентир на курс (GigaChat)

llm_batch_size: 1    # ответов на один вызов LLM (1 = без батчинга, вердикты независимы)
```

Пути из `paths` — значения по умолчанию; флаги CLI (`--input`, `--reference`,
`--output`) их переопределяют. `token_budget` — мягкий ориентир: при его
превышении CLI печатает предупреждение, но не прерывает работу.

> `llm_batch_size: 1` выбран намеренно — батчинг делает оценку строже и меняет
> часть вердиктов; поднимать его стоит только после повторной валидации против
> эталона.

## 4. Ключи API

### 4.1. Через файл `.env` (основной способ)

Скопируйте шаблон `.env.example` в `.env` (файл `.env` не коммитится) и
заполните нужные переменные:

```dotenv
# Иностранная группа: OpenRouter
OPENROUTER_API_KEY=sk-or-...

# Российская группа: GigaChat
GIGACHAT_CREDENTIALS=...
GIGACHAT_SCOPE=GIGACHAT_API_PERS
```

`config.yaml` ссылается на эти переменные **по имени** (`api_key_env`,
`scope_env`); сами ключи в `config.yaml` и в код никогда не попадают. При
запуске `.env` подхватывается автоматически (`python-dotenv`).

Если включён режим с обращением к LLM, но ключ не задан, система выдаёт
понятную русскую ошибку, например:

```
Не задан ключ API: переменная окружения OPENROUTER_API_KEY пуста.
Заполните её в файле .env (см. .env.example).
```

> Для код-only-прогонов (`--max-llm-calls 0` без ИИ-выводов) ключ **не нужен** —
> система работает полностью на коде.

### 4.2. Через экран «Настройки» (опциональный оверлей)

В веб-интерфейсе на экране **«Настройки»** можно:

- выбрать модель/провайдера **отдельно** для трёх компонентов:
  `analysis` (анализ), `insight` (ИИ-выводы), `chat_agent` (чат);
- при необходимости ввести ключи прямо в UI.

Эти переопределения сохраняются в локальный файл-оверлей `output/settings.json`
(не коммитится). Порядок разрешения значений всегда:

```
UI-оверлей  >  config.yaml  >  встроенное значение по умолчанию
```

Ключи, введённые через UI, хранятся локально, **маскируются** в любом
представлении и никогда не записываются в `config.yaml` или исходники. Система
по-прежнему полностью работоспособна на одном `.env`.

## 5. Запуск веб-интерфейса

Веб-интерфейс состоит из двух процессов: **бэкенд** (FastAPI/uvicorn) и
**фронтенд** (Vite dev-сервер).

### 5.1. Бэкенд

Из корня проекта (виртуальное окружение активировано):

```powershell
uvicorn web.app:app --port 8000
```

Для разработки удобен авто-перезапуск:

```powershell
uvicorn web.app:app --reload
```

По умолчанию бэкенд слушает `http://127.0.0.1:8000`. На этом адресе уже доступен
серверный прототип (Jinja-шаблоны) и весь API: загрузка и анализ, история
прогонов, сравнение, чат (`/chat`, `/threads`, `/settings`, `/analyze`,
`/compare`, `/runs`, `/history`, `/download`).

### 5.2. Фронтенд (React SPA)

В отдельном терминале:

```powershell
cd web/frontend
npm run dev
```

Vite поднимет дев-сервер (по умолчанию `http://localhost:5173`) и **проксирует**
API-вызовы SPA на бэкенд. Прокси настроен в `web/frontend/vite.config.ts`:
запросы по путям `/chat`, `/threads`, `/settings`, `/analyze`, `/compare`,
`/runs`, `/history`, `/download` уходят на бэкенд, а навигация браузера по тем
же путям отдаёт `index.html` SPA (диспетчеризация по заголовку `Accept`).

Цель прокси по умолчанию — `http://127.0.0.1:8000`. Если бэкенд запущен на
другом порту, укажите его через переменную окружения **`VITE_API_TARGET`**
(см. раздел 8).

### 5.3. Продакшен-сборка

Для статической поставки соберите фронтенд и отдавайте `web/frontend/dist/`
любым веб-сервером, оставив бэкенд (`uvicorn web.app:app`) как API:

```powershell
cd web/frontend
npm run build
```

## 6. Запуск через CLI (`main.py`)

CLI-точка входа — `main.py` (argparse). Базовый вызов из корня проекта:

```powershell
.venv\Scripts\python.exe main.py --input ./data/samples/021 --reference ./data/etalon/021 --output ./output
```

### 6.1. Флаги

| Флаг | Обяз. | По умолчанию | Назначение |
|------|:----:|--------------|------------|
| `--input` | да | — | файл или папка с ответами пользователей (Массив) |
| `--reference` | нет | — | файл или папка с эталонными ответами (Эталон) |
| `--output` | нет | `./output` | папка для отчётов |
| `--mode` | нет | `all` | какие модули запускать: `answer` \| `time` \| `report` \| `all` (`report` = answer+time, затем отчёт) |
| `--model-group` | нет | из `config.yaml` | группа нейросетей: `foreign` \| `russian` |
| `--model` | нет | из `config.yaml` | разовая замена slug модели |
| `--max-llm-calls` | нет | `0` | максимум обращений к LLM на курс (`0` = без LLM, только код) |
| `--insights` | нет | `""` | разделы ИИ-выводов через запятую: `diagnosis,why_failed,recommendations,anomalies` (дёшево — 1 вызов на курс) |
| `--insight-note` | нет | `""` | свободное пожелание к ИИ-выводам |

### 6.2. Примеры

**Бесплатный детерминированный прогон (без LLM, 0 токенов):**

```powershell
.venv\Scripts\python.exe main.py --input ./data/samples/021 --reference ./data/etalon/021 --output ./output
```

**Только сравнение ответов с обращением к LLM (курс 001, свободный текст):**

```powershell
.venv\Scripts\python.exe main.py --input ./data/samples/001 --reference ./data/etalon/001 --mode answer --max-llm-calls 20
```

**Российская группа (GigaChat) с ИИ-выводами:**

```powershell
.venv\Scripts\python.exe main.py --input ./data/samples/069 --reference ./data/etalon/069 --model-group russian --max-llm-calls 20 --insights diagnosis,recommendations
```

**Разовая замена модели OpenRouter:**

```powershell
.venv\Scripts\python.exe main.py --input ./data/samples/021 --reference ./data/etalon/021 --model deepseek/deepseek-v4-flash
```

После прогона CLI печатает по каждому курсу: число попыток, вопросов,
критических вопросов, LLM-вызовов (и попаданий в кэш), токенов и стоимости, а в
конце — суммарные токены/стоимость и список путей к отчётам. Сбои на отдельном
курсе изолируются — остальные курсы обрабатываются, выдаётся частичный
результат.

## 7. Данные и вывод

### 7.1. Входные данные

| Папка | Содержимое | Парсер |
|-------|------------|--------|
| `data/samples/<курс>/` | **Массив ответов** пользователей (`.xlsx`); один лист = один тест | `pipeline.parsers.answer_array_parser` |
| `data/etalon/<курс>/` | **Эталон ответов** (ключ); связывается с массивом по нормализованному тексту вопроса (в эталоне нет ID) | `pipeline.parsers.reference_parser` |

В репозитории три демонстрационных курса — **001 / 021 / 069**:

- **001** — задания со свободным текстом; оцениваются LLM (`answer_agent`),
  поэтому к этому курсу осмысленно применять `--max-llm-calls > 0`.
- **021 / 069** — выбор/сопоставление/ранжирование; оцениваются
  детерминированно средствами LMS (без обращения к нейросети).

> Эти три курса — рабочий регрессионный набор. Не ужесточайте валидацию
> настолько, чтобы валидные данные 001/021/069 переставали обрабатываться.

`AnswerCache` (`output/.cache/answer_cache.json`) делает оценочные вердикты LLM
детерминированными и кэшируемыми между прогонами.

### 7.2. Вывод

- `output/` — сгенерированные отчёты (по курсам).
- `output/settings.json` — локальный оверлей настроек из веб-интерфейса
  (не коммитится).
- `output/.cache/answer_cache.json` — кэш вердиктов `AnswerCache`.

История прогонов и сравнение доступны в веб-интерфейсе (экраны «История» и
«Сравнение»); отчёты — по маршрутам `/download/<id>.docx` (Word), `/download/<id>.pdf` (PDF печатает Chromium-браузер,
уже установленный на компьютере: Edge, Chrome, Яндекс, Opera, Brave; свой путь можно задать переменной
среды `KORPUS_PDF_BROWSER`) и `/download/<id>.xlsx` (Excel; `?sections=summary,questions` — сводка и цифры по
вопросам). JSON и текст доступны по `/download/<id>.json` и `.txt`, но в интерфейсе не показываются.
Параметры нового анализа (группа моделей, глубокий анализ, лимит обращений 500, аспекты) задаются в
«Настройках» и хранятся в `output/settings.json` (`analysis_defaults`); значения по умолчанию — в `config.yaml`
(`analysis_defaults`, `thresholds.pass_score`).

## 8. Типовые проблемы и их решение

**Не задан ключ API.**
Симптом: `Не задан ключ API: переменная окружения OPENROUTER_API_KEY пуста`.
Решение: заполните `.env` (см. `.env.example`) либо введите ключ на экране
«Настройки». Для код-only-прогона (`--max-llm-calls 0`, без `--insights`) ключ
не требуется.

**Порт 8000 занят.**
Запустите бэкенд на другом порту и сообщите его прокси фронтенда:

```powershell
uvicorn web.app:app --port 8010
```

```powershell
# тот же терминал фронтенда, перед npm run dev:
$env:VITE_API_TARGET = "http://127.0.0.1:8010"
npm run dev
```

**Не найдены входные файлы.**
Симптом: `Не найдено входных файлов (.xlsx) по указанному пути.`
Решение: проверьте `--input` — путь должен указывать на `.xlsx` или на папку с
ними (например, `./data/samples/021`).

**Ошибки TLS у GigaChat.**
По умолчанию в `config.yaml` стоит `verify_ssl: false`. Для строгой проверки
установите корневой сертификат Минцифры и выставьте `verify_ssl: true`.

**Превышен бюджет токенов.**
CLI печатает предупреждение `превышен бюджет токенов` при выходе за
`token_budget`. Это не ошибка; уменьшите объём данных, понизьте
`--max-llm-calls` или пересмотрите `token_budget` в `config.yaml`.

**Проблемы с фронтендом / Node.**
Убедитесь, что установлен Node.js 18+ (Vite 6). При странных сбоях удалите
`web/frontend/node_modules` и повторите `npm install`.

## 9. Бюджет и экономика запуска

Проект уложен в бюджет **≤ 10 000 ₽** и спроектирован так, чтобы основная часть
работы шла **бесплатно**:

- **Сначала код, LLM — в последнюю очередь.** По умолчанию `--max-llm-calls 0` —
  детерминированный прогон без обращения к нейросети, стоимость **0 токенов**.
  Курсы 021/069 оцениваются полностью кодом и не требуют LLM вовсе.
- **GigaChat (российская группа)** — используется бесплатный тариф **Lite**
  (наибольший бесплатный лимит, 900 000 токенов), чего с запасом хватает на
  демонстрацию и регулярную работу.
- **OpenRouter (иностранная группа)** — порядка **~1 ₽ за прогон** благодаря
  компактной модели и отключённому «рассуждению» (`reasoning: false`,
  `max_tokens: 1024`).
- **Кэш и батч-настройки.** `AnswerCache` исключает повторную оплату одинаковых
  вердиктов; `token_budget` сигнализирует о перерасходе на курс.

Таким образом, регулярная эксплуатация для методиста практически бесплатна, а
полный бюджет championship-кейса остаётся существенно ниже лимита — это прямое
конкурентное преимущество решения.
